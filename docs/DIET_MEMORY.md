# 饮食记忆与多样性（Stage 4）

服务器记录最近 **10 次完成的有效进食**。多样饮食奖励额外恢复和料理增益；重复饮食保留完整基础营养和恢复。只需继续吃东西即可改变状态，不使用现实时间冷却，不增加攻击、护甲、移动速度、最大生命或新 HUD。

所有系数是机制原型。按用户要求，战斗节奏与数值评估、微调留到主要功能和机制基本完成后进行。

## 记录时机与保存

生存/冒险玩家成功完成带 Food Component 的物品消费后，沿用已有完成进食入口，按顺序执行：

1. 查询本次服务端 Food Profile，保存 `food_id`、`quality`、`categories`、`variety_group`、`timestamp` 快照。
2. 添加到队尾，超过十次时移出最旧一条。多类别料理仍只占一条。
3. 按更新后的窗口计算奖励，应用到本次食物恢复量和增益时长；后续 Well-fed tick 使用当前窗口。

`timestamp` 是主世界 `gameTime` tick，用于记录，不决定有效期；跨维度使用同一时间来源。同 tick 内的多次完成消费按实际调用顺序保存，不丢弃；没有等待现实时间的门槛。持有物品、未完成消费、普通无 Food Component 的药水不写记录，创造/旁观模式不写记录。世界方块直接提供营养（例如原版蛋糕）不经过现有物品完成消费入口，本阶段不新增该入口。

fallback 食物同样记录：Basic、空类别、独立物品 ID 作为组。不凭空推断未知类别。数据包重载只影响未来进食；旧记录保留当时字段，随新进食自然滚出。

新增独立 Fabric Attachment `buildup_vitals:diet_memory`，保存 `entries` 列表，顺序从旧到新。最多十条、类别不重复且不超过六种；未知 Quality/Category 或超长窗口由 Codec 拒绝。合法但已不存在的物品/组 ID 仍可作为历史标识保存。旧 Recovery / Meal Benefit 附件格式和范围不变。

死亡清空，不随死亡重生复制；活着替换玩家、跨维度、保存重进和断线重连保留。离线期间不遗忘，不跨玩家共享。未有附件的旧存档从空窗口开始。评分由保存的条目重新计算，不另存倍率；不可变状态缓存结果，进食/读档时计算，不在每 tick 遍历历史。

## 奖励公式

以下是调试/数据包作者说明，普通玩家只需理解“跨类别的饮食更有价值”。

对一组权重 `w`，有效种类数定义为 `E(w) = (Σw)² / Σ(w²)`；空集合为 0。均匀分布的多种食物得分较高，大量重复会降低有效种类数。设 `D(E) = clamp((E−1)/3, 0, 1)`，四种有效种类即可到达对应维度上限，无需集齐六类别。

- **类别 C**：每次已知类别的进食贡献总权重 1，多类别料理在各类别均分。计算类别的 `D(E)` 后，乘以窗口中有类别记录的比例，避免未知食物凭空增加类别覆盖。
- **食物组 G**：每次进食向其 `variety_group` 贡献权重 1，计算 `D(E)`。不同物品但同组仍按同一种组计。
- **Quality Q**：Basic / Prepared / Meal / Feast 的权重为 0 / 1⁄3 / 2⁄3 / 1，取窗口平均；其影响弱于类别和组。
- **单组限制 H**：`clamp(有效组数−1, 0, 1)`，确保反复吃同一种多类别 Feast 不会单独拿到多样饮食奖励。
- **窗口完整度 F**：`条目数 / 10`，新玩家从短窗口逐步建立奖励。

```text
score = clamp(F × (0.65 × C × H + 0.25 × G + 0.10 × Q × G), 0, 1)
repeat = 1 − 0.10 × (同食物 ID 或同组的记录数 − 1) / 9
```

`repeat` 相对最新一餐计算，范围 0.90–1.00，同一条记录不会重复计数。即使数据包改变同物品的组，相同 `food_id` 仍算重复。重复会影响分布评分，同时最多再扣除 10% 的**额外奖励部分**。

| 应用 | 最终计算 | 保持不变的边界 |
|---|---|---|
| 食物恢复储备 | `基础 Recovery × (1 + 0.15 × score × repeat)` | 零恢复仍为零；总储备上限 20 HP；只在进食时加入一次 |
| 料理增益时长 | `floor(基础时长 × (1 + 0.10 × score × repeat))` | 最长仍 3600 tick；同类不缩短、异类替换；不增加效果强度 |
| Well-fed 速度 | 目标倍率 `1 + 0.075 × score × repeat`；周期 `ceil(80 / 倍率)` | 实际周期 75–80 tick，最多每次 1 HP；每 HP 仍支付 6 Exhaustion |
| Stable / Food 兑现周期 | 原有规则 | Stable 120 tick；Food 50 tick，Restorative 40 tick |
| Hunger / Saturation | 原版 Food Component | 从不按饮食乘算、扣减或锁定 |

所有最终收益倍率均从 **1.0** 起算。`repeat=0.9` 不代表吃同一种食物只得到 90% 恢复；它只作用于多样性额外奖励。单组长期饮食 `score=0`，回到完整基础。Restorative 不改变储备总量；Variety 奖励是在进食时明确加入的额外储备，两者职责不同。

Well-fed 的整数周期向上取整，所以实际加速不超过目标倍率；最高 80→75 tick，约 +6.67% 速度。切换饮食保留已有周期进度，最多下个 tick 兑现一次，不补发多个周期。Food Recovery 优先、自然恢复游戏规则及受击不中断行为延续原规则。

## 数据与查询

内置牛排 Basic / protein、面包 Basic / grain 两份最小类别示例，不新增 Recovery 或 Benefit。结合已有苹果/水果 Tag、蘑菇煲、南瓜派可验证三种饮食；更广泛的食谱平衡仍留待后续。

```text
/buildupvitals diet
/buildupvitals diet <player>
/buildupvitals recovery
```

前两个命令需 Game Masters 权限，显示十次历史、类别/组/Quality 分项、score、repeat、最终倍率和 Well-fed 周期，均只读。`food_multiplier` 是此窗口的奖励水平；下一餐会先滚动窗口再计算，不是无条件给任意下一餐锁定此值。

## 机制验收

在测试世界中生存并允许命令，每次等有 Hunger 空间后正常进食，查询历史：

- A：连续 10 次牛排；营养不衰减，窗口成为单组，所有最终倍率为 1.0。
- B：轮换苹果、西瓜片、甜浆果共 10 次；只有 fruit 类别，组更多，有少量奖励但达不到跨类别高分。
- C：轮换牛排、面包、蘑菇煲、苹果、南瓜派各两次；跨类别奖励应高于 B，料理恢复及增益时长带少量额外收益。
- 从 C 连续改吃牛排，旧记录逐条退出，到第十次后恢复 A；无需等待现实时间。
- 满血或重进世界不清空记录；跨维度和重连保留，死亡清空。

本轮只验收记录、奖励边界和原版行为保持；三组饮食的体验差距与数值舒适度以后统一评估。
